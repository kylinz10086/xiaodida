# 体验指南（10 分钟跑通一单）

> 目标：在同一小程序里，先当**用户**发一单，再切**骑手**接单送达，最后回用户确认收货，看到钱进账。

前置：云端已部署好（`xyyx-user` / `xyyx-rider` / `xyyx-pay` / `xyyx-cron` 都在 `env-00jy72ju8b4z`）。

## 二、先当用户，发一单

1. 首页右上角「微信登录」→ 勾选协议 → 微信一键登录；
2. 点「代取快递」或「代带餐食」；
3. 填标题（4~40 字）、金额（1~1000 元，最多两位小数）、手机号、取件/送达地点；
4. 点「发布任务」；
5. 当前没有商户证书，会弹「模拟支付」确认框；点「确认支付」后订单进入大厅；
6. 去「订单」Tab 可看到待接单。

> 后台发生：订单落库 `pay_status=paid` + 一条 `escrow_in` 托管流水。

---

## 三、切成骑手身份

1. 「我的」→「🛵 骑手中心」；
2. 首次显示未认证 → 申请成为骑手；
3. 填真实姓名/学号/手机号 → 提交；
4. 后台「骑手审核」通过后，状态变成已认证骑手。

> 冷启动规则：平台没有已通过骑手时，第一个申请自动通过；之后由后台审核。
> 管理后台：<http://127.0.0.1:5180/admin/> → 骑手审核 → 通过/拒绝。

---

## 四、接单 → 送达 → 确认收货

1. 骑手中心 → 抢单大厅 → 抢一单（不能抢自己发布的）；
2. 我的任务 → 已取件 → 已送达；
3. 切回用户身份 → 订单 → 确认收货；
4. 骑手钱包余额 +90%，平台留 10% 佣金。

## 五、支付说明

- 当前仓库没有 `xyyx-pay/pay-config.js`，所以 `getPayMode()` 返回 `mock`；
- 发布任务时会出现「模拟支付」确认框，确认后写 `pay_status=paid`，这是开发环境行为；
- 真实微信支付 V3 代码已实现（下单/签名/回调验签/解密），但需要：
  - 商户号 `mchid`
  - API v3 密钥
  - 商户私钥 + 证书序列号
  - 平台证书公钥
  - 配置到 `pay-config.js`（已 gitignore）
- 没有这些配置时，`wechat` 分支不会真实扣款。

## 六、常见问题

| 现象 | 处理 |
| --- | --- |
| 抢单提示「你还不是骑手」 | 后台审核通过，`rider_status=2` |
| 抢单提示「不能接自己发布的单」 | 换另一个微信号 |
| 支付弹窗直接失败 | 没配商户证书时应走 mock；检查 `pay-config.js` |
| 页面一直转圈/「云端未就绪」 | 云对象未部署或域名未配 |
| 订单大厅看不到 | 只有 `pay_status=paid` 才进大厅 |
| 骑手看不到手机号 | 故意的：接单前不给，接单后只给脱敏号 |
| 首页之前登录条被卡片遮挡 | 已移除登录条，改为右上角「微信登录」 |

## 七、域名 / 真机

uniCloud 请求域名：

```text
https://env-00jy72ju8b4z.api-hz.cloudbasefunction.cn
```

- 开发者工具：详情 → 本地设置 → 不校验合法域名；
- 真机 / 上线：微信公众平台 → 开发管理 → 开发设置 → 服务器域名 → request 合法域名添加并保存；
- 浏览器直接打开根域名返回 `50002` 是正常，因为根路径没有 HTTP 函数路由；实际云对象用 POST `/functions/invokeFunction`。
