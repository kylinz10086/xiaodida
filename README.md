# 校递达 · 校园跑腿小程序

浙江中医药大学的校园快递代取 / 代带餐食互助平台。
**一个小程序，进去选身份**（用户 / 骑手）+ **uniCloud 后端（支付宝云）**，资金走「预付托管」。

```
用户下单付款 ──▶ 平台托管 ──▶ 骑手接单 ──▶ 送达 ──▶ 结算（平台服务费 8%）
```

> 体验入口与账号见 [测试目录.md](测试目录.md)；部署见 [docs/usage.md](docs/usage.md)。

- 原图取不到时一直显示缩略图，不会白屏/转圈。

- **图片分片读取，不再限大小**：云函数 `getImageData` 改成按 192KB 分片返回，客户端拼起来

  不再只是灰块。
- **提现页**：去掉「人工审核 / 1-3 个工作日」那段说明（提现已自动处理）。
- 版本号显示同步到 `v1.9.8`。

## 2026-11-13 下午 · v1.9.7（第二轮图片修复 + 自动提现）

> 已出正式包并上传微信后台开发版本 **1.9.7**；真机预览码：`docs/code-v197-preview.jpg`。

- **图片兜底：旧图也能显示了**。上一版只修了「新发的图」（带缩略图），历史消息里的
  `cloud://` 图片仍然裂。这版新增云对象 `getImageData(fileID)`：云函数把图片从云存储读出来
  以 base64 返回，客户端再用 data URI 显示 —— 只走 callFunction 的 request 域名，
  **完全不依赖 downloadFile 域名白名单，也不怕临时链接过期**。聊天图片、订单图片、
  取件/送达留痕都接了这条兜底。
- **图片更清晰**：聊天图片上传从 1080/q60 提到 **1440/q70**，留痕照片 **1600/q75**；
  预览时优先取原图（云函数取回），取不到才退回缩略图。缩略图本身也从 400px 提到 480px。
- **头像分两档**：`avatar`（240px，列表/聊天用）+ `avatar_hd`（720px，只在「我的」页返回），
  头像更清楚，又不会把列表接口撑爆。
- **提现去掉人工审核**：之前是「扣余额 → 冻结 → 等审核」，但后台根本没有审核/打款入口，
  钱提出来就永远卡在「审核中」。现在改成自动处理（扣余额、累计已提现、写流水），
  并用代码做风控：认证骑手才能提、单笔 ≤200 元、每天 ≤5 次、单日累计 ≤500 元、
  两次间隔 10 分钟、扣款用 CAS 防并发超提；历史遗留的冻结金额下次提现时自动退回余额。
- **版本号可见**：「我的」页底部显示 `v1.9.7 · 体验版/开发版/正式版`，排查「改了没生效」用。
- 回归测试：图片用例扩到 **39 项**，加上金额 76、骑手 65，共 180 项全过。

## 2026-11-13 图片修复（头像 / 聊天图片 / 订单图片）· v1.9.6

> 版本号：`1.9.6`（versionCode 196），已出正式包并上传微信后台开发版本；
> 真机预览码：`docs/code-image-fix-20261113.jpg`。

- **头像存不进去**：客户端已经把头像压成 data URI，但云对象 `updateProfile` 还留着
  `max: 300` 的旧校验，几 KB 的 data URI 直接被判「头像过长」→ 头像永远保存失败。
  现在放宽到 16KB 并校验格式（`data:image/…` / `/static/…` / http），客户端压到
  240px，超了自动降档再压。
- **聊天图片显示不出来**：之前只存 `cloud://` fileID，展示要靠 `getTempFileURL`
  的临时链接 —— 小程序 `<image>` 走的是 downloadFile 域名白名单，云存储 CDN 域名
  没配就整片裂图；临时链接还会过期，旧消息过一阵子同样打不开。
  现在发图片时同时生成一张**缩略图 data URI** 跟消息一起存，气泡直接画它：
  不发额外请求、不看域名、不会过期。原图仍然传云存储，点开预览时优先用原图，
  取不到就退回缩略图。
- **订单图片 / 取件送达留痕**：同一套问题，发布订单和拍照留痕时也带上缩略图
  （`image_thumbs` / `pick_proof_thumb` / `deliver_proof_thumb`）。
  为了不把返回体撑爆：**只有详情接口下发缩略图，列表接口不带**。
- **老数据兼容**：没有缩略图的历史消息/订单继续走临时链接，链接拿不到时显示灰底
  而不是裂图图标；`cloud://` 头像退回默认头像。
- **回归测试**：新增 `tests/image-flow.spec.js`（30 项断言：头像上限、缩略图落库、
  详情/列表的字段边界、聊天图片、留痕缩略图）。

## 2026-11-12 晚 改了什么

- **订单内聊天**：用户和骑手在订单里直接聊（文字 + 图片），4 秒增量轮询，未读红点、会话列表，
  入口在订单详情 / 骑手任务详情 / 我的-消息 / 骑手中心-消息。
- **订单详情页重做**：状态时间线（已支付 → 已接单 → 已取件 → 已送达 → 已完成）、骑手卡片、
  真实数据走 `getTaskDetail`（不再依赖本地缓存），底部按钮按身份和状态只给能用的。
- **协议与规则重写**：用户协议、隐私政策、跑腿服务协议、**骑手准则（新增）**、平台规则摘要、
  算法公示。去掉模板腔，写清楚 8% 服务费、退款、24 小时确认、禁运品、处罚与申诉。
- **合规入口补齐**：意见反馈、注销账号（写 `xyyx-feedback`，15 个工作日内处理）、
  联系客服；隐私政策里补充聊天记录与图片的收集说明。
- **评价闭环**：订单完成后发布者可 1-5 星 + 快捷标签 + 文字评价；骑手详情展示最近 3 条评价；
  列表出现「待评价」角标。后端补 `listReviews` / `getRiderProfile`，评分不再永远 5.0。
- **履约留痕**：骑手点「已取件 / 已送达」时可以选择拍照，图片存到订单的
  `pick_proof` / `deliver_proof`，用户端时间线能看缩略图（跳过拍照也能继续）。
- **发布页提效**：自动带出上次的取件/送达地址；按距离和物品大小给三档建议价（仍可自定义）；
  类型收敛为 3 类。
- **订阅消息脚手架**：`common/notify.js` 统一放模板 id，发布成功后请求「接单/送达」授权；
  没配模板 id 时静默跳过，不影响下单。
- **界面打磨**：骑手工作台、我的、订单、骑手中心、钱包、申请页统一视觉；金额统一两位小数；
  空态、骨架屏、底部安全区、缺失图标全部修掉。
- **费率调整**：抽佣 **8%**、单笔提现 **3 元**起（代码默认值、云端 `xyyx-settings`、协议文案已同步）。
- **修掉的真问题**：
  - 云端部署的 `xyyx-common` 是旧版（抽佣 8%），与仓库 5% 不一致 → 重新部署并统一为当前的 8%；
  - 任务图片上传走的是外部七牛 + 别人的 `upToken` 服务 → 换成云函数中转上传；
  - 真机 `uniCloud.uploadFile` 报 `url not in domain list`（OSS 域名没进 uploadFile 白名单）
    → 图片改走「压 base64 → 云对象 uploadImage → 服务端写 /tmp 再传云存储」，不再依赖上传域名；
  - 头像保存的是本地临时路径（别人看不到）→ 压缩成 data URI 存资料，所有端都能显示；
  - 发布页「代购」会存成 `type=4` 被服务端拒绝 → 收敛为 3 类，和骑手端筛选一致；
  - 骑手详情只显示脱敏手机号（拨号却用完整号）→ 接单后正常显示完整号；
  - 登录失败弹窗把 errMsg / 探测日志甩给用户 → 改成看得懂的提示，细节进控制台；
  - 删除老模板遗留的 amap 导航页、七牛上传、i18n、`api.youzixy.com` 请求层等无用依赖。
- **仓库整理**：删除归档的 `apps/rider`、历史演示版 `miniprogram/`、一次性调试脚本、
  Chrome 调试 profile、过期截图；`unpackage/`、`node_modules/` 等仍在 `.gitignore`。

## 快速开始

需要：HBuilderX（已登录 DCloud 账号）+ 微信开发者工具（已扫码登录）+ 已绑定的 uniCloud 空间。

```powershell
# 1. 配密钥（仓库里没有真实密钥）
copy "apps\user\uniCloud-alipay\cloudfunctions\common\uni-config-center\uni-id\config.example.json" `
     "apps\user\uniCloud-alipay\cloudfunctions\common\uni-config-center\uni-id\config.json"
# 然后把里面的占位符换成真实值

# 2. 打开工程
& "F:\HBuilderX.5.05.2026032417\HBuilderX\cli.exe" project open --path "F:\xiaodida\apps\user"

# 3. 编译到微信小程序
& "F:\HBuilderX.5.05.2026032417\HBuilderX\cli.exe" launch mp-weixin --project "F:\xiaodida\apps\user" --compile true
# 产物：apps/user/unpackage/dist/dev/mp-weixin，用开发者工具打开这个目录
```

云端部署（数据库、云对象、支付）详见 **[docs/usage.md](docs/usage.md)**。

## 一个 App，两种身份怎么隔离

| 层 | 做法 |
| --- | --- |
| 接口 | 用户端只能调 `xyyx-user`，骑手端只能调 `xyyx-rider`，方法集不重叠 |
| 字段 | 服务端 `taskForUser()` / `taskForRider()` 两套白名单 |
| 数据 | 所有集合 `permission: false`，客户端无法直连数据库 |
| 聊天 | 只有该订单的发布者和骑手是成员，服务端 `assertChatMember` 兜底 |

**骑手接单前拿不到任何手机号**；接单后能看到完整号码（要打电话），
用户永远拿不到骑手的真名、学号、学校。

## 安全

- 密码 `scrypt` + 每用户随机盐 + pepper（不用明文、不用裸哈希）
- 写接口带 nonce 防重放，按 uid 限流，参数白名单
- 记账有 `idempotency_key` 唯一索引，重复回调不重复入账
- 聊天消息纯文本入库，仅订单双方可读，限流 30 条/分钟
- 仓库零密钥：提交前跑 `node tools/scripts/check-secrets.mjs`

详见 **[docs/security.md](docs/security.md)**。
