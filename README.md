# 校递达 · 校园跑腿小程序

浙江中医药大学的校园快递代取 / 代带餐食互助平台。
**一个小程序，进去选身份**（用户 / 骑手）+ **uniCloud 后端（支付宝云）**，资金走「预付托管」。

```
用户下单付款 ──▶ 平台托管 ──▶ 骑手接单 ──▶ 送达 ──▶ 结算（平台服务费 8%）
```

## 2026-11-17 · v1.2.12（消息里点开对话没反应 —— 真正的原因）

`v1.2.11` 修的是服务端查询，但用户反馈「还是打不开」。用微信开发者工具自动化
（`tools/scripts/probe-mp-chat.cjs`，真的点一下那一行）才定位到：**点击事件根本没进到方法里**。

编译出来的 wxml 是这样的：

```
列表页（坏的）: data-event-opts="{{[['tap',[['openChat',['$0'],[[['conversations','convKey(c)',c.m0]]]]]]]}}"
聊天页（正常）: data-event-opts="{{[['tap',[['openPreview',['$0'],[[['messages','_id',m.$orig._id]]]]]]]}}"
```

uni-app 的参数回填是「按 key 在数组里找原对象」。`:key="convKey(c)"` 这种**方法调用**写法，
会让它把 `convKey(c)` 整串当成属性名去查 `item['convKey(c)']` —— 永远 undefined，
于是 `openChat(undefined)`，页面毫无反应、console 也没有异常。

根子是我在 1.2.9 为了绕开「小程序 `:key` 不支持 `||` 表达式」，把 key 挪进了方法，反而踩了这个坑。

- 列表页改成 `v-for="(c, i)"` + `:key="i"` + `:data-idx="i"` + `@click="openRow"`，
  方法不带 v-for 参数，从 `dataset` 拿下标 —— 完全不碰那套参数回填。
- 顺手扫了全站：`pages/` 下只有这一处把方法写进 `:key`，没有同类隐患。
- 会话「共 N 个订单」与列表页对齐，都按**真聊过的订单**算（之前列表 4、点进去 6）。

> 验证（真机式自动化）：列表 1 条会话，`peer_id` 唯一；点开跳转到
> `pages/chat/chat?peer=...&taskId=...&role=user`，`loadErr` 为空，60 条消息，
> 来源分布 我 26 / 对方 24 / 系统 10，**第三方消息 0 条**。
> 上传记录：2026-11-17 21:35 小程序 **1.2.12**；`xyyx-common` 已重新部署。
> 测试：194 通过 / 18 失败（基线未变）。

## 2026-11-17 · v1.2.11（消息会话：打不开 / 串台 / 老记录丢失）

接 1.2.10 之后用户反馈「我的 → 消息里对话打不开」。用内存库把会话链路跑了一遍，
问题不在页面跳转，而在 `chatThreadWithPeer` 的两个查询条件：

- **串台（不同聊天对象串在一起）**：合并会话原来只按 `task_id` 取消息。
  同一单「先被别人接过、放弃后换人」时，他和上一个人的私聊也挂在这个 `task_id` 下，
  点开 A 的会话会看到 A 和别人的对话。现在查询加了一对方条件
  `(from_id,to_id)` 必须是「我和他」，系统提示（接单/放弃）保留。
- **订单被清掉，那半段聊天记录整段消失**：原来只有「一个共同订单都找不到」时才用消息反推订单，
  只要还剩一单，被删的那单下的消息就全被过滤掉了 —— 会话看起来像被清空、「打不开」。
  现在改成**两路取并集**：还在的订单 ∪ 消息里出现过的订单。
- 发消息的落点也一起改了：进行中的订单 → 最近聊过的那单 → 最新订单，订单被清也能发出去。
- 小程序端：加载失败不再只弹一个一闪而过的 toast，页面上留错误卡片 + 「重新加载」按钮；
  合并会话里跨订单处加一条订单标题分隔；列表页打开失败有提示（页面栈满以前是静默失败）。

> 上传记录：2026-11-17 12:00 小程序 **1.2.11**；云函数 + `xyyx-common` 已全量部署。
> 测试：193 通过 / 18 失败（基线 18 条仍是佣金 8%、提现迁移、结算语义那批过期断言）。
> 新增测试段 16：会话按人聚合 / 不串台 / 删单后仍可读 —— 会话这块以前一条覆盖都没有。

## 2026-11-14 · 修「钱到账了但显示失败，还把余额退回去」

- 线上现象：后台一笔 ¥1 提现显示「转账失败：请求中含有未在API文档中定义的参数」，
  但用户微信里**已经到账**，系统还把余额退回去了 —— 一笔钱记成两笔。
- 根因：`applyTransferState` 只凭 HTTP 错误 / `state=FAIL` 就冲正余额，**没有先问微信**。
  参数类报错不代表钱没出去；再加上「参数降级重试」会换一档参数用同一个单号再试，
  很容易出现「第一次其实已经建单 → 后面报错 → 当成失败退款」。
- 修法（`xyyx-pay`）：
  - 新增 `probeBillState(outBillNo)`：任何「失败」结论落地前，先查微信这张单的真实状态。
    - 有单且成功/在途 → 按真实状态落库，**绝不冲正**；
    - 查不到（网络/权限）→ 标 `pending`，交给定时任务再对账，**不擅自退钱**；
    - 只有微信明确「没有这张单」或 `FAIL/CANCELLED/EXPIRED` 才冲正。
  - 参数降级重试前同样先查单：有单就不再换参数重试。
- 后台新增 **「对账」** 按钮（`xyyx-pay.reconcileWithdraw`）：以微信侧为准修正本地记录；
  「已到账但之前误退过」的情况会把多退的余额扣回来并补一条对账流水（余额不足则标记人工核账）。

## 2026-11-14 · 提现出口 IP 会变怎么办（固定 IP 转发器）

云函数公网出口是 NAT 池，IP 会变；而微信「商家转账」要求把调用方 IP 加进**接口安全IP**白名单。
IP 一变就报 `此IP地址不允许调用接口，请按开发指引设置`。

**先看清现状**：后台 → 提现记录 → 「查出口IP」（连查 3 轮 × 4 个回显服务，列出所有可能出口），
失败单的行里也会显示这次实际用的 IP（`egress_ip`）。如果只有 2~5 个、几天内不变，
把它们全加进白名单就够了。

**想一劳永逸**：让微信只看到一个固定 IP —— 加一台有固定公网 IP 的机器做转发。

```
小程序 → 云函数（签名在云函数里做，私钥不出服务器）
              │  POST /forward（HMAC-SHA256 签名）
              ▼
        固定 IP 的服务器（tools/wechat-relay.cjs）
              │  原样透传 header + body
              ▼
        api.mch.weixin.qq.com
```

1. 固定 IP 的机器上（1 核 1G 够用）：

   ```bash
   RELAY_SECRET='一串够长的随机字符串' PORT=8787 node tools/wechat-relay.cjs
   curl http://127.0.0.1:8787/ip        # 拿这台机器的公网 IP
   ```

2. 这个 IP 加到 微信商户平台 → 产品中心 → 商家转账 → 接口安全IP。
3. `pay-config.js` 里打开转发：

   ```js
   relay: { url: 'https://你的域名/forward', secret: '同一串密钥' }
   ```

4. 重新部署 `xyyx-pay`。之后所有微信支付/退款/转账都走这台机器，白名单配一次长期有效。

安全：转发器只透传 `Authorization` 和 body，**不接触商户私钥**；签名带时间戳（5 分钟过期）防重放；
`/forward` 校验 HMAC，建议前面套 nginx HTTPS 并限制来源。

## 2026-11-13 图片修复（头像 / 聊天图片 / 订单图片）· v1.9.6

> 版本号：`1.9.6`（versionCode 196），已出正式包并上传微信后台开发版本；
> 真机预览码：`docs/code-image-fix-20261113.jpg`。

- **头像存不进去**：客户端已经把头像压成 data URI，但云对象 `updateProfile` 还留着
  `max: 300` 的旧校验，几 KB 的 data URI 直接被判「头像过长」→ 头像永远保存失败。
  现在放宽到 16KB 并校验格式（`data:image/…` / `/static/…` / http），客户端压到
  240px，超了自动降档再压。
- **聊天图片显示不出来**：之前只存 `cloud://` fileID，展示要靠 `getTempFileURL`
  的临时链接 —— 小程序 `<image>` 走的是 downloadFile 域名白名单，云存储 CDN 域名
  没配就整片裂图；临时链接还会过期，旧消息过一阵子同样打不开。
  现在发图片时同时生成一张**缩略图 data URI** 跟消息一起存，气泡直接画它：
  不发额外请求、不看域名、不会过期。原图仍然传云存储，点开预览时优先用原图，
  取不到就退回缩略图。
- **订单图片 / 取件送达留痕**：同一套问题，发布订单和拍照留痕时也带上缩略图
  （`image_thumbs` / `pick_proof_thumb` / `deliver_proof_thumb`）。
  为了不把返回体撑爆：**只有详情接口下发缩略图，列表接口不带**。
- **老数据兼容**：没有缩略图的历史消息/订单继续走临时链接，链接拿不到时显示灰底
  而不是裂图图标；`cloud://` 头像退回默认头像。
- **回归测试**：新增 `tests/image-flow.spec.js`（30 项断言：头像上限、缩略图落库、
  详情/列表的字段边界、聊天图片、留痕缩略图）。

## 一个 App，两种身份怎么隔离

| 层 | 做法 |
| --- | --- |
| 接口 | 用户端只能调 `xyyx-user`，骑手端只能调 `xyyx-rider`，方法集不重叠 |
| 字段 | 服务端 `taskForUser()` / `taskForRider()` 两套白名单 |
| 数据 | 所有集合 `permission: false`，客户端无法直连数据库 |
| 聊天 | 只有该订单的发布者和骑手是成员，服务端 `assertChatMember` 兜底 |

**骑手接单前拿不到任何手机号**；接单后能看到完整号码（要打电话），
用户永远拿不到骑手的真名、学号、学校。

## 安全

- 密码 `scrypt` + 每用户随机盐 + pepper（不用明文、不用裸哈希）
- 写接口带 nonce 防重放，按 uid 限流，参数白名单
- 记账有 `idempotency_key` 唯一索引，重复回调不重复入账
- 聊天消息纯文本入库，仅订单双方可读，限流 30 条/分钟
- 仓库零密钥：提交前跑 `node tools/scripts/check-secrets.mjs`

详见 **[docs/security.md](docs/security.md)**。
